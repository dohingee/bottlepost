# 첫 출시 가이드 (Google Play)

순서대로 진행합니다. ✋ 표시는 **직접** 해야 하는 일, 🤖 표시는 Claude/자동화가 하는 일입니다.
비밀번호·키 파일 내용은 채팅에 붙이지 마세요. GitHub 비밀값 화면에만 넣습니다.

전체 흐름:
- 1~3단계: 계정과 키를 준비합니다.
- 4~5단계: 출시 파일(.aab)을 만듭니다.
- 6~8단계: Play Console에 앱을 등록합니다.
- 9~10단계: 내부 테스트로 내 폰에서 먼저 확인합니다.
- 11단계: 테스터 12명과 14일 동안 비공개 테스트를 합니다.
- 12단계: 프로덕션(정식 출시)을 신청합니다.

## 1. ✋ 앱 전용 Gmail 만들기
- https://accounts.google.com/signup 에서 예: `bottlepost.help@gmail.com`을 만듭니다.
- 이 주소는 개인정보처리방침·이용약관·아동 안전 페이지, 앱의 "문의하기", 스토어 연락처에 **공개**됩니다.
- 만든 주소와 "개인정보 보호책임자" 표시 이름(실명 또는 "보틀포스트 운영자")을 Claude에게 알려 주세요.
- 🤖 Claude가 문서와 앱에 반영하고 push합니다. 웹 페이지(bottlepost.web.app)는 자동으로 다시 배포됩니다.

## 2. ✋ Play Console 개발자 계정 만들기
1. https://play.google.com/console/signup 에 접속합니다. 개인 Gmail 또는 1단계의 전용 Gmail 중 하나를 고릅니다.
   - 계정 소유자 메일은 나중에 바꾸기 어려우니 오래 쓸 계정으로 고르세요.
2. **개인(Personal)** 계정을 선택하고 등록비 25달러를 결제합니다(1회).
3. 신원 확인을 진행합니다.
   - 법적 이름, 주소, 신분증(주민등록증·운전면허증·여권), 전화번호 인증을 거칩니다.
   - 안내가 나오면 휴대폰에 "Play Console" 앱을 설치해 기기 확인도 합니다.
   - 승인까지 보통 1~3일, 길면 일주일쯤 걸립니다. 기다리는 동안 3~5단계를 하면 됩니다.

## 3. ✋ 업로드 키 만들기 (한 번만, 평생 보관)
업로드 키는 "이 파일은 내가 올린 것"을 증명하는 열쇠입니다. Play가 사용자에게 배포할 때는 Google이 관리하는 별도 키(Play 앱 서명)로 다시 서명합니다. 그래서 업로드 키를 잃어버려도 Play 고객센터에 재설정을 요청할 수 있지만, 몇 주가 걸리니 잘 보관하세요.

1. Android Studio → 아래쪽 **Terminal** 탭을 엽니다(PowerShell).
2. 아래 두 줄을 그대로 붙여 넣고 Enter를 누릅니다.
   ```powershell
   cd $HOME\Documents
   & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore bottlepost-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
   ```
3. 질문에 답합니다.
   - 비밀번호: 영문·숫자로 12자 이상. 두 번 입력합니다.
   - 이름·조직·도시 등: 아무 값이나 넣어도 되고, 엔터만 눌러도 됩니다. 마지막 확인 질문에는 `y`를 입력합니다.
4. `문서` 폴더에 `bottlepost-upload.jks` 파일이 생깁니다. 이 파일과 비밀번호를 비밀번호 관리자나 개인 클라우드 등 **두 군데 이상**에 보관하세요.
5. 같은 터미널에서 키 파일을 글자로 바꿔 클립보드에 복사합니다.
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\Documents\bottlepost-upload.jks")) | Set-Clipboard
   ```

## 4. ✋ GitHub 비밀값 등록
GitHub에서 `dohingee/bottlepost` 저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**을 눌러 아래 3개를 만듭니다.

| Name | Secret에 넣을 값 |
|---|---|
| `UPLOAD_KEYSTORE_BASE64` | 3-5에서 복사한 긴 글자(Ctrl+V) |
| `UPLOAD_KEYSTORE_PASSWORD` | 3-3에서 정한 비밀번호 |
| `UPLOAD_KEY_PASSWORD` | 같은 비밀번호 |

`FIREBASE_SERVICE_ACCOUNT` 비밀값과 `FIREBASE_PROJECT_ID` 변수는 이미 있습니다. 앱 설정 파일(google-services.json)은 워크플로가 이것으로 Firebase에서 직접 받아 오므로 따로 올릴 필요가 없습니다.

## 5. 출시 파일(.aab) 만들기
1. ✋ GitHub 저장소 → **Actions** → 왼쪽 **Android release bundle** → 오른쪽 **Run workflow** → 초록 **Run workflow** 버튼을 누릅니다.
   - Claude에게 "출시 빌드 돌려 줘"라고 해도 됩니다.
2. 🤖 약 10~15분 동안 테스트, 검사, 빌드, 서명이 진행됩니다.
   - 실패하면 빨간 X 화면 위쪽에 원인이 표시됩니다(예: "GitHub secret UPLOAD_KEY_PASSWORD is not set").
   - Claude도 같은 내용을 읽을 수 있습니다.
3. ✋ 성공(초록 체크)하면 그 실행 화면 맨 아래 **Artifacts**에서 `bottlepost-aab`를 내려받습니다.
   - zip 압축을 풀면 `app-release.aab`가 나옵니다.
   - 버전 번호(versionCode)는 실행할 때마다 자동으로 1씩 커집니다.

## 10. ✋ 출시 앱이 서버에 접속하도록 등록 (중요)
출시 앱은 Play Integrity로 "진짜 앱"임을 증명합니다. 아래를 하지 않으면 편지 보내기 등 모든 기능이 거절됩니다.

1. Play Console → **테스트 및 출시 → 앱 무결성**에서 지문을 확인합니다.
   - **앱 서명 키 인증서**의 SHA-1·SHA-256을 확인합니다.
   - 같은 화면에서 **업로드 키 인증서**의 SHA-1·SHA-256도 확인합니다.
2. 같은 화면 **Play Integrity API → Cloud 프로젝트 연결**에서 `bottlepost` 프로젝트를 선택합니다.
3. Firebase 콘솔 → ⚙️ **프로젝트 설정 → 내 앱 → Android 앱 → 디지털 지문 추가**를 누릅니다.
   - 위 4개(SHA-1 2개, SHA-256 2개)를 하나씩 추가합니다.
   - 구글 계정 연결이 출시 앱에서 동작하려면 필요합니다.
4. Firebase 콘솔 → **App Check → 앱 → Android 앱 → Play Integrity → 등록**을 누릅니다.
   - SHA-256 칸에는 **앱 서명 키**의 SHA-256을 넣고 저장합니다.
5. 휴대폰에서 앱을 완전히 닫았다 다시 엽니다.
   - 편지 보내기, 답장, 번역, 구글 연결을 해 봅니다.
   - 문제가 있으면 Claude에게 알려 주세요.

## 11. 비공개 테스트: 12명 × 14일 (개인 계정 필수 조건)
1. ✋ 테스터 12명 이상을 모읍니다. 가족, 친구, 테스터 교환 커뮤니티 등에서 구합니다.
   - 각자 Gmail 주소가 필요합니다.
   - **12명 모두가 14일 동안 연속으로 참여 상태여야** 합니다. 여유 있게 15~20명을 권장합니다.
2. ✋ **테스트 → 비공개 테스트 → 트랙 만들기**를 합니다.
   - 테스터 이메일 목록을 추가합니다.
   - 같은 .aab(또는 새로 빌드한 것)로 새 버전을 만듭니다.
   - **검토 후 출시**를 누릅니다. 첫 심사는 보통 며칠 걸립니다.
3. ✋ 승인되면 "웹에서 참여" 링크를 테스터들에게 보냅니다. 각자 링크에서 테스터가 된 뒤 설치하면 됩니다.
4. 🤖 테스트 중 수정 사항이 생기면 Claude가 고쳐서 push합니다.
   - 5단계로 새 .aab를 만들어 같은 트랙에 새 버전을 올리면 됩니다.
   - 테스터 14일 집계는 이어집니다.

## 12. ✋ 프로덕션 출시 신청
- 비공개 테스트 14일이 지나면 대시보드에 **프로덕션 액세스 신청**이 열립니다.
- 테스트 방법, 받은 피드백, 출시 준비 상태에 대한 설문에 솔직하게 답합니다. Claude에게 초안을 부탁해도 됩니다.
- 승인되면 **프로덕션 → 새 버전**에 .aab를 올립니다.
- **단계적 출시 20%**로 시작해서, 며칠간 Crashlytics 비정상 종료율이 1% 미만이면 100%로 늘립니다.

## 13. ✋ 광고 켜기 (정식 출시 후)
1. AdMob → 앱 → 보틀포스트 → **앱 설정 → 앱 스토어 정보 추가**에서 Play 스토어의 보틀포스트를 연결합니다. 그러면 AdMob 앱 검토가 시작됩니다(며칠).
2. 승인되면 Firebase 콘솔 → **Remote Config** → 매개변수 추가: `ads_enabled` = `true`(불리언) → **변경사항 게시**.
   - 몇 시간 안에 사용자 앱에 반영됩니다.
   - 끄려면 `false`로 바꿔 게시합니다.
   - 간격·상한은 `ads_interstitial_min_interval_sec`(기본 180), `ads_skip_first_letters`(기본 1), `ads_max_per_day`(기본 5)로 조절합니다.
3. 그 전까지 출시 앱에는 광고가 나오지 않습니다. 디버그 앱(Android Studio 실행)은 항상 Google **테스트 광고**만 보여 줍니다.
4. 같은 스위치가 편지 보내기 전 전면광고와 메인 화면 하단 배너를 함께 켜고 끕니다.
